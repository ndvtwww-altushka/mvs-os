# MVS OS в виртуальной машине

Виртуальная машина — это настоящая MVS OS, запущенная в окне. Хост
не перезагружается, установщик видит виртуальный диск, а не реальный.
Закрыли окно — система выключилась; открыли снова — всё на месте.

Это удобно, если:

- нельзя перезагрузить компьютер;
- компьютер после перезагрузки сбрасывается;
- нужно проверить установщик, не трогая реальный диск;
- нужно держать MVS OS под рукой, не размечая винчестер.

## Быстрый путь

Первый запуск — создаётся диск и открывается установка с ISO:

```sh
sh tools/make-vm.sh --install
```

Внутри QEMU:

1. дождитесь рабочего стола Live;
2. запустите **«Установить MVS OS»**;
3. выберите диск **24 GB VirtIO** (`/dev/vda`);
4. создайте пользователя и пароль;
5. завершите установку и закройте окно QEMU.

Дальше — обычный запуск, уже без ISO:

```sh
sh tools/make-vm.sh
```

Диск VM по умолчанию лежит в `~/.local/share/mvs-os/mvs.qcow2`.
Его можно скопировать на внешний диск как резервную копию.

## Что нужно

```sh
sudo apt install qemu-system-x86 qemu-utils
```

Для ускорения нужен `/dev/kvm` и членство в группе `kvm`:

```sh
sudo usermod -aG kvm "$USER"
```

После этого нужно выйти и войти снова. Без KVM всё работает, но медленно.

## Настройки

Переменные окружения:

- `MVS_ISO` — путь к ISO;
- `MVS_VM_DISK` — путь к диску VM;
- `MVS_VM_SIZE` — размер нового диска (по умолчанию `24G`);
- `MVS_RAM` — память в МБ (по умолчанию `4096`);
- `MVS_CPUS` — число ядер (по умолчанию `4`);
- `MVS_VGA` — `std` или `virtio`.

Пример с диском на внешнем носителе:

```sh
MVS_VM_DISK=/media/disk/mvs.qcow2 sh tools/make-vm.sh
```

Так система переживёт сброс компьютера, если внешний диск не отключают.

## Вручную, без скрипта

```sh
qemu-img create -f qcow2 mvs.qcow2 24G

qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -nic user,model=e1000 \
  -drive file=mvs.qcow2,if=virtio \
  -cdrom MVS-OS-1.0-amd64.iso -boot d
```

После установки — без `-cdrom` и с `-boot c`.

## Что работает, а что нет

Работает: рабочий стол, темы, приложения MVS, LibreOffice, Thunderbird,
VLC, терминал, файлы, apt, обновления, сеть через NAT.

Ограничения виртуальной машины:

- **Wi-Fi** — VM видит проводной `eth0`, реальные Wi-Fi сети не пробрасываются;
- **3D-ускорение** — слабее, чем на железе;
- **звук** — может не заработать без настройки QEMU/PulseAudio;
- **USB** — флешки нужно пробрасывать вручную;
- **загрузчик** — устанавливается в виртуальный диск; это не проверка
  загрузки на конкретном NVMe/UEFI-железе.

## Установка на реальную флешку из VM

Технически можно отдать QEMU целевую флешку как диск:

```sh
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -cdrom MVS-OS-1.0-amd64.iso -boot d \
  -drive file=/dev/sdb,format=raw,if=virtio
```

Но это опасно: ошибка в `/dev/sdb` стирает не ту флешку, а GRUB,
поставленный для виртуального BIOS, может не совпасть с UEFI целевого ПК.
Для реальной флешки надёжнее `tools/write-usb.sh` и загрузка с неё.

## Честно об автоматизации

Calamares не поддерживает полностью автоматическую установку без
подтверждений. Скрипт `make-vm.sh` автоматизирует всё вокруг: проверку
ISO, создание диска, выбор режима загрузки и запуск QEMU. Но диск, имя
пользователя и пароль вы выбираете в установщике сами — это сделано
специально, чтобы установка не могла стереть диск «сама».
