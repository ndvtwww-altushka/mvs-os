# MVS OS в виртуальной машине

Виртуальная машина — это настоящая MVS OS, запущенная в окне. Хост
не перезагружается, установщик видит виртуальный диск, а не реальный.
Закрыли окно — виртуальная машина выключилась. В Live-режиме изменения
не сохраняются; в установленном — остаются на виртуальном диске.

Это удобно, если:

- нельзя перезагрузить компьютер;
- компьютер после перезагрузки сбрасывается;
- нужно проверить установщик, не трогая реальный диск;
- нужно держать MVS OS под рукой, не размечая винчестер.

## Просто посмотреть ISO в окне

Ничего устанавливать не нужно: QEMU загружает ISO как Live-систему.
С флешки — положи `make-vm.sh` и ISO в одну папку:

```sh
sh make-vm.sh --live
```

Из репозитория:

```sh
sh tools/make-vm.sh --live
```

Откроется окно MVS OS. Крестик закрывает VM и возвращает в Linux —
хост не перезагружался, изменения в Live-режиме не сохраняются.

Если окно не влезает в экран (гость просит 1280×800, а монитор меньше):

```sh
sh make-vm.sh --live --fullscreen
```

Или прямо в окне VM нажмите `Ctrl+Alt+F` — полный экран и обратно.
Окно можно и просто перетащить за заголовок: картинка внутри
масштабируется под размер окна.

## Alt+Tab между MVS OS и Linux

Окно QEMU — обычное окно рабочего стола, и по умолчанию оно **не
захватывает клавиатуру**. Поэтому:

- `Alt+Tab` переключает на окно Linux и обратно — как с любым приложением;
- клик по окну MVS OS возвращает клавиатуру виртуальной машине;
- крестик закрывает VM, Linux продолжает работать.

Если клавиатура всё-таки захвачена (например, включён `MVS_GRAB=1` или
выбран пункт меню **View → Grab Input**), нажмите `Ctrl+Alt+G` — QEMU
отпустит ввод, после чего `Alt+Tab` снова работает.

Нужен `Alt+Tab` **внутри** MVS OS, между её окнами? Запустите с захватом:

```sh
MVS_GRAB=1 sh make-vm.sh --live
```

Тогда `Alt+Tab` переключает окна гостя, а на рабочий стол Linux ведёт
`Ctrl+Alt+G`.

`Ctrl+Alt+F` — полный экран и обратно. `Ctrl+Alt+2` открывает монитор
QEMU, команда `quit` — аварийный выход, `Ctrl+Alt+1` — назад в систему.

Скрипт сам ищет ISO рядом с собой, в текущей папке и в `~/Downloads`.
Сначала берётся образ ровно той версии, что указана в `VERSION`
(сейчас 1.4), а если его нет — самый новый из найденных: старые ISO
рядом не должны запускаться по ошибке. Если QEMU нет:

```sh
sudo apt install qemu-system-x86   # Debian/Ubuntu
```

## Установить в виртуальный диск

Первый запуск — создаётся диск и открывается установка с ISO:

```sh
sh tools/make-vm.sh --install
```

Внутри QEMU:

1. дождитесь рабочего стола Live;
2. запустите **«Установить MVS OS»**;
3. выберите диск **24 GB VirtIO** (`/dev/vda`);
4. создайте пользователя и пароль;
5. завершите установку и закройте окно QEMU.

Дальше — обычный запуск, уже без ISO:

```sh
sh tools/make-vm.sh
```

Диск VM по умолчанию лежит в `~/.local/share/mvs-os/mvs.qcow2`.
Его можно скопировать на внешний диск как резервную копию.

## Что нужно

```sh
sudo apt install qemu-system-x86 qemu-utils
```

Для ускорения нужен `/dev/kvm` и членство в группе `kvm`:

```sh
sudo usermod -aG kvm "$USER"
```

После этого нужно выйти и войти снова. Без KVM всё работает, но медленно.

## Настройки

Переменные окружения:

- `MVS_ISO` — путь к ISO;
- `MVS_VM_DISK` — путь к диску VM;
- `MVS_VM_SIZE` — размер нового диска (по умолчанию `24G`);
- `MVS_RAM` — память в МБ (по умолчанию `4096`);
- `MVS_CPUS` — число ядер (по умолчанию `4`);
- `MVS_VGA` — `auto`, `std` или `virtio` (по умолчанию `auto`);
- `MVS_NIC` — параметры сети QEMU (по умолчанию `user,model=virtio-net-pci`);
- `MVS_AUDIO` — `auto`, `1` или `0` — звук через PulseAudio/PipeWire;
- `MVS_GL=1` — OpenGL в окне (быстрее графика, если драйвер хоста дружит);
- `MVS_GRAB=1` — захват клавиатуры для `Alt+Tab` внутри VM;
- `MVS_DISPLAY` — `gtk` или `sdl`, если автоматика ошиблась.

Пример с диском на внешнем носителе:

```sh
MVS_VM_DISK=/media/disk/mvs.qcow2 sh tools/make-vm.sh
```

Так система переживёт сброс компьютера, если внешний диск не отключают.

## Почему в окне быстрее

Скрипт по умолчанию включает то, что даёт кратный выигрыш в VM:

- **virtio-net** вместо эмулируемой e1000 — сеть в VM работает в разы
  быстрее и меньше грузит CPU хоста;
- **virtio-vga** вместо std VGA — рабочий стол рисуется заметно плавнее;
- **iothread + writeback** для диска — чтение и запись идут параллельно
  с работой процессора, а не по очереди;
- **KVM + `-cpu host`** — гость исполняет код прямо на ядре хоста.

Если на конкретном компьютере virtio-видео не заведётся, вернитесь на
проверенный режим:

```sh
MVS_VGA=std sh tools/make-vm.sh --live
```

## Вручную, без скрипта

```sh
qemu-img create -f qcow2 mvs.qcow2 24G

qemu-system-x86_64 -enable-kvm -cpu host -m 4096 -smp 4 \
  -object iothread,id=mvsio \
  -nic user,model=virtio-net-pci \
  -device qemu-xhci -device usb-tablet -vga virtio \
  -drive file=mvs.qcow2,if=none,id=mvsdisk,cache=writeback \
  -device virtio-blk-pci,drive=mvsdisk,iothread=mvsio \
  -cdrom MVS-OS-1.4-amd64.iso -boot d
```

После установки — без `-cdrom` и с `-boot c`.

## Что работает, а что нет

Работает: рабочий стол, темы, приложения MVS, LibreOffice, Thunderbird,
VLC, терминал, файлы, apt, обновления, сеть через NAT.

Ограничения виртуальной машины:

- **Wi-Fi** — VM видит проводной `eth0`, реальные Wi-Fi сети не пробрасываются;
- **3D-ускорение** — слабее, чем на железе;
- **звук** — может не заработать без настройки QEMU/PulseAudio;
- **USB** — флешки нужно пробрасывать вручную;
- **загрузчик** — устанавливается в виртуальный диск; это не проверка
  загрузки на конкретном NVMe/UEFI-железе.

## Установка на реальную флешку из VM

Технически можно отдать QEMU целевую флешку как диск:

```sh
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -cdrom MVS-OS-1.4-amd64.iso -boot d \
  -drive file=/dev/sdb,format=raw,if=virtio
```

Но это опасно: ошибка в `/dev/sdb` стирает не ту флешку, а GRUB,
поставленный для виртуального BIOS, может не совпасть с UEFI целевого ПК.
Для реальной флешки надёжнее `tools/write-usb.sh` и загрузка с неё.

## Честно об автоматизации

Calamares не поддерживает полностью автоматическую установку без
подтверждений. Скрипт `make-vm.sh` автоматизирует всё вокруг: проверку
ISO, создание диска, выбор режима загрузки и запуск QEMU. Но диск, имя
пользователя и пароль вы выбираете в установщике сами — это сделано
специально, чтобы установка не могла стереть диск «сама».
