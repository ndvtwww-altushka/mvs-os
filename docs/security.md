# Безопасность MVS OS

## Главный принцип

**Live и установленная система — не одно и то же.**

| | Live | Установленная |
| --- | --- | --- |
| Вход | автологин `mvs` | логин + пароль |
| sudo | без пароля (`90-mvs-live`) | пароль пользователя |
| PolicyKit | без запроса (`49-mvs-live.rules`) | обычные запросы |
| Срок жизни | до перезагрузки | постоянный |
| Диск компьютера | не изменяется | изменяется только установщиком |

Демо-послабления существуют ровно для того, чтобы систему можно было
попробовать с флешки. Установщик удаляет их первым же шагом
(`docs/installer.md`), а не «когда-нибудь потом».

## Права

- Пользователь установленной системы создаётся в группе `sudo`.
- Root-пароль не задаётся: административные действия — через `sudo`.
- `sudoers.d/10-mvs-hardening`: `env_reset`, `secure_path`, `use_pty`,
  таймаут пароля 10 минут, журнал `/var/log/sudo.log`.
- `polkit` используется графическими программами (pkexec). В Live
  правило `49-mvs-live.rules` разрешает действия пользователю `mvs`;
  в установленной системе этого файла нет.
- Root не входит в графическую сессию: `allow-root=false`.

## Сеть

- `ufw` установлен, политика: входящие `DROP`, исходящие `ACCEPT`.
- Единственное входящее исключение — mDNS `5353/udp`: без него Avahi
  не находит сетевые принтеры и сканеры. Остальное закрыто.
- В установленной системе `ENABLED=yes` — правила применяются при загрузке.
- Управление: MVS Control Center → Безопасность (реальный `ufw`).
- `sysctl.d/90-mvs-hardening.conf`: `rp_filter`, запрет redirect,
  SYN-cookies, запрет IP forwarding.

## Ядро

- `kernel.kptr_restrict=2`, `dmesg_restrict=1`, `yama.ptrace_scope=1`.
- `protected_hardlinks`, `protected_symlinks`, `protected_fifos`,
  `protected_regular` — защита от подмены файлов в общих папках.
- `fs.suid_dumpable=0` — setuid-программы не оставляют core dump.
- ASLR включён.

## AppArmor

- Пакет `apparmor`, служба включена.
- Загрузка Live идёт с `security=apparmor apparmor=1`.
- Профили берутся из пакетов Debian; дополнительных профилей проект
  не пишет, поэтому и не обещает «полную изоляцию всего».

## Обновления

- apt принимает только подписанные репозитории:
  `Acquire::AllowInsecureRepositories=false`.
- Автоматически ставятся только обновления **безопасности**
  (`unattended-upgrades`, `51mvs-unattended-upgrades`).
- Обычные обновления — вручную через MVS Update (`apt-get dist-upgrade`).
- Перезагрузка после обновлений не автоматическая.
- MVS Update показывает реальный код выхода apt; ошибка не превращается
  в «успех».

## Диагностика

- MVS Doctor проверяет диск, память, сбойные службы, `ufw`, AppArmor,
  доступные обновления, маршрут и NTP без root.
- Отчёт сохраняется в домашнюю папку обычным текстом; красная строка —
  повод посмотреть подробности, а не приговор системе.

## Защита от случайного удаления

- Thunar: удаление в корзину с подтверждением (`MiscUseTrash`,
  `MiscConfirmDelete`).
- MVS Cleaner работает только с кэшем, журналами и корзиной; домашние
  папки не сканирует на удаление.
- MVS Backup создаёт tar.gz и не удаляет исходники.
- Установщик требует явного подтверждения перед разметкой диска.

## Резервное копирование

MVS Backup копирует `Documents`, `Pictures`, `Desktop`, `Downloads`,
`Videos`, `Music` и настройки MVS. Восстановление распаковывает архив
в выбранную папку и предупреждает о замене файлов.

## Что НЕ сделано (честно)

- Нет шифрования домашней папки и диска «из коробки».
- Нет собственных AppArmor-профилей для приложений MVS.
- Нет антивируса: для Linux-десктопа это не обязательный компонент.
- Нет централизованного аудита (`auditd`) — журналы остаются штатными.
- Пароль пользователя проверяется Calamares на минимальную длину, но
  собственная политика сложности в этой версии не реализована.
