# Тестирование: что проверено, а что нет

Главное правило проекта: **не выдавать непроверенное за работающее**.
Ниже — честная таблица.

## Автоматические проверки

| Проверка | Где | Что ловит |
| --- | --- | --- |
| `sh tools/check-packages.sh` | CI и `build.sh` | опечатки и отсутствующие в bookworm пакеты — до сборки |
| `sh check.sh` | локально и CI | синтаксис sh, XML/SVG, `.desktop`, иконки, списки пакетов, наборы Store, версии, наличие конфигов Calamares |
| Python `compile()` | CI | синтаксические ошибки всех `.py` |
| JSON | CI | битый `presets.json` |
| YAML | CI | ошибки в `settings.conf` и модулях Calamares |
| `lb build` | CI | несуществующие пакеты, ошибки хуков, сборка squashfs/ISO |
| QEMU smoke BIOS | CI (информационный) | ISO стартует, framebuffer не пустой, нет паники ядра |
| QEMU smoke UEFI | CI (информационный) | то же через OVMF: UEFI-загрузчик стартует, framebuffer не пустой |

QEMU-тест **не** проверяет установщик, звук, Wi-Fi и реальные драйверы.
Он отвечает только на вопрос «ISO вообще загружается».

## Ручная проверка Live (чек-лист)

Что нужно пройти на реальной машине или в VirtualBox/VMware:

- [ ] загрузка в UEFI;
- [ ] загрузка в Legacy BIOS;
- [ ] экран входа, автологин `mvs`;
- [ ] панель, меню «Пуск», ярлыки рабочего стола;
- [ ] MVS Hub запускает все 13 приложений;
- [ ] Store: вкладки «Наборы», «Поиск», «Журнал»; установка набора идёт с журналом;
- [ ] Store: набор VS Code честно предлагает подключить репозиторий, а не падает;
- [ ] Doctor: проверка запускается, отчёт сохраняется в домашнюю папку;
- [ ] Control Center: кнопка Doctor открывает диагностику;
- [ ] Control Center: экран, звук, сеть, Bluetooth, питание;
- [ ] Store: обновление индексов, поиск, установка пакета;
- [ ] Update: проверка и установка обновлений;
- [ ] LibreOffice: Writer, Calc, Impress, проверка орфографии;
- [ ] Thunderbird запускается и создаёт учётную запись;
- [ ] VLC открывает видео и звук;
- [ ] блокировка экрана (`light-locker`), возврат по паролю;
- [ ] Catfish находит файл по имени;
- [ ] связка ключей: пароль Wi-Fi сохраняется после перезагрузки;
- [ ] сканер в сети находится через `sane-airscan`;
- [ ] сетевая папка открывается в Thunar (`smb://`);
- [ ] Cleaner: оценка и очистка кэша;
- [ ] Backup: создание и распаковка архива;
- [ ] Games: все пять игр;
- [ ] смена темы в Quick Settings и Control Center;
- [ ] Wi-Fi: подключение к сети с паролем;
- [ ] звук: громкость, mute, микрофон;
- [ ] яркость (ноутбук);
- [ ] спящий режим и блокировка экрана;
- [ ] принтер (если есть).

## Ручная проверка установки

- [ ] установщик видит диск;
- [ ] предупреждение о стирании диска;
- [ ] создание пользователя с паролем;
- [ ] установка на UEFI;
- [ ] установка на Legacy BIOS;
- [ ] после перезагрузки: вход по паролю, автологина нет;
- [ ] `sudo -n true` в установленной системе **не** проходит без пароля;
- [ ] `ufw status` — активен;
- [ ] `systemctl is-active apparmor` — активен;
- [ ] `/var/log/mvs-install.log` без критических ошибок;
- [ ] повторная загрузка Live-флешки не сломала установленную систему.

## Что в этом окружении проверить нельзя

Проект собирался в Android-окружении без bash, python3, live-build и x86_64.
Поэтому:

- ISO **не собирался** здесь — только в GitHub Actions;
- Python-приложения **не запускались** — проверяется только синтаксис;
- `check-packages.sh` проверен на локальном наборе `Packages`; сверка
  с живым архивом Debian выполняется в CI (здесь нет curl/wget и xz);
- Calamares **не запускался** — проверена структура конфигов;
- скрипты `make-vm.sh`, `write-usb.sh`, `build-local.sh` проверены
  только на синтаксис `sh -n`; QEMU, запись USB и apt на хосте здесь
  выполнить нельзя;
- UEFI-загрузка в QEMU не запускалась здесь — только в CI;
- железо (Wi-Fi, Bluetooth, NVIDIA) **не проверялось**.

Если сборка в CI упала — это ожидаемо для первой итерации; лог покажет
конкретный пакет или файл. Не считайте проект «готовым» до прохождения
чек-листов выше.

## Как быстро проверить себя

```sh
sh ./check.sh
sh tools/check-packages.sh
python3 -m compileall -q config/includes.chroot/usr/lib/mvs
```

Виртуалка без установки:

```sh
sh tools/make-vm.sh --install
```

Или вручную:

```sh
qemu-system-x86_64 -m 3072 -enable-kvm \
  -cdrom MVS-OS-1.0-amd64.iso -boot d
```

С установкой (диск-образ 20 ГБ):

```sh
qemu-img create -f qcow2 mvs-disk.qcow2 20G
qemu-system-x86_64 -m 3072 -enable-kvm -smp 2 \
  -cdrom MVS-OS-1.0-amd64.iso \
  -drive file=mvs-disk.qcow2,if=virtio \
  -boot d
```

Для UEFI добавьте `-bios /usr/share/ovmf/OVMF.fd` (путь зависит от
дистрибутива).

Тот же тест, что в CI, можно запустить вручную:

```sh
python3 tests/qemu_smoke.py MVS-OS-1.0-amd64.iso
python3 tests/qemu_smoke.py --uefi MVS-OS-1.0-amd64.iso
```

Скрипт сохраняет `boot.ppm` / `boot-uefi.ppm`, `serial*.log` и `qemu*.log`.
