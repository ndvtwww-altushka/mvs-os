# Изменения MVS OS

## 1.4 «Aurora Nova»

Главное изменение — откат системы снимками btrfs. Остальное закрывает
проблемы, из-за которых системе нельзя было доверять: версия в шести
местах, вопросы dpkg, зависшие окна и небезопасный Backup.

### Вход в Live

- В список Live добавлен `user-setup`. Без него компонент
  `live-config/0030-user-setup` молча выходит, пользователь `mvs`
  не создаётся, и экран входа отвергает любой пароль. Ошибка была
  в 1.0; теперь сборка падает, если пакета нет в образе.
- Раскладка по умолчанию — английская (`us,ru`), русская по Alt+Shift:
  пароль `live` на экране входа набирается как ожидается.

### Откат снимками btrfs

- Установка по умолчанию — btrfs с субтомами `@`, `@home`, `@snapshots`
  (`mount.conf`, `partition.conf`). Снимки лежат рядом с `@`, а не внутри
  него, поэтому не попадают в следующие снимки.
- `mvs-snapshot create|list|delete|promote` — снимок корня, список,
  удаление и назначение снимка загрузочным по умолчанию. Хранятся
  10 последних; снимок, из которого загружены, не удаляется.
- `/etc/grub.d/40_mvs_snapshots` добавляет в меню GRUB подменю
  «MVS OS — откат к снимкам». Снимок грузится своим ядром, а его
  `/etc/fstab` заранее указывает на собственный субтом — иначе systemd
  попытался бы перемонтировать корень в `@`.
- MVS Update делает снимок перед `dist-upgrade` и показывает состояние
  снимков в отдельной карточке. Ошибка снимка не блокирует обновление,
  но честно пишется в журнал.
- `btrfs-progs` добавлен в список пакетов установщика.

### Идентичность MVS

- `mvs-identity` держит `/etc/os-release`, `/usr/lib/os-release` и
  `/etc/lsb-release` под `dpkg-divert`: обновление `base-files` больше
  не возвращает «Debian GNU/Linux».
- Скрипт вызывается из `DPkg::Post-Invoke`, службы `mvs-identity.service`,
  хука сборки и установщика — то есть после apt из терминала тоже.

### Версия в одном файле

- `VERSION` и `CODENAME` — единственный источник версии. `build.sh`
  генерирует `/etc/mvs-version`, `/etc/mvs-codename`, `os-release` и
  `lsb-release`; приложения читают версию оттуда.
- Статические `os-release`/`lsb-release` удалены из исходников, чтобы
  не было второй версии. `check.sh` следит за этим.

### Обновления и Store без вопросов dpkg

- apt запускается с `DEBIAN_FRONTEND=noninteractive`,
  `--force-confdef` и `--force-confold`: изменённые конфиги сохраняются,
  вопрос «What do you want to do about modified configuration file?»
  больше не вешает окно.
- `DPkg::Lock::Timeout=120` — apt ждёт освобождения блокировки, а не
  падает сразу.

### Приложения не зависают

- MVS Update: `apt-get update`, список обновлений, снимок и установка —
  в фоне.
- MVS Store: список установленных пакетов, поиск, проверка набора —
  в фоне; установка и удаление идут через неинтерактивный apt.
- MVS Cleaner: размеры считаются через `os.walk` без внешнего `du`,
  очистка выполняется в отдельном потоке.

### Backup

- Архив и его `.part` исключаются из самого архива.
- Обход папок идёт по одному элементу: нечитаемый файл или сокет
  пропускается с записью в журнал, а не срывает всю копию.
- При восстановлении проверяются пути, абсолютные и выходящие за папку
  симлинки, жёсткие ссылки и особые файлы. Пропущенное перечисляется
  в журнале.

### Релизы и проверка

- QEMU-тест больше не считает меню GRUB успешной загрузкой: он нажимает
  Enter и ждёт маркер `MVS_BOOT_OK`. Маркер пишет служба `mvs-boot-check`
  только после того, как `live-config` создал пользователя `mvs` и LightDM
  поднял его сеанс XFCE. Раньше снимок меню с логотипом Debian проходил
  проверку «экран не пустой».

- GitHub Actions: `checks → build → qemu (BIOS, UEFI, Secure Boot) →
  release`. Релиз создаётся только при успехе всех трёх загрузок;
  раньше QEMU был информационным и стоял после публикации.
- QEMU-тест проверяет не «файл не пустой», а что на экране система:
  доля цветных точек и число оттенков. Экран «Secure Boot violation»
  больше не считается успешной загрузкой.
- Версия для артефактов и тега берётся из `VERSION`.

## Улучшения в этом репозитории

Исправления поверх исходников 1.0 — без смены версии и без выдуманных
«новых возможностей».

### Приложения

- **MVS Store**: индексы apt в bookworm лежат как `..._Packages.lz4`, а не
  `Packages`. Старая проверка всегда отвечала «индексы не загружены»;
  теперь учитываются сжатые списки. Список установленных пакетов читается
  одним вызовом `dpkg-query` вместо сотни — поиск и наборы открываются
  заметно быстрее.
- **MVS Backup**: папки находятся через `xdg-user-dir`, поэтому русские
  «Документы», «Изображения» и «Загрузки» больше не выглядят пустыми.
  Архив собирается модулем `tarfile` в фоновом потоке, а не внешним `tar`:
  код выхода 1 от предупреждений больше не считается успехом. Восстановление
  использует `tarfile.data_filter` (или ручную проверку путей на старом
  Python) и не может распаковаться за пределы выбранной папки.
- **MVS Update**: ошибка `apt-get update` больше не выдаётся за
  «обновлений нет» — состояние и кнопка установки честно сбрасываются.
- **MVS Control Center**: состояние ufw не запрашивается через pkexec при
  каждом открытии окна — только по кнопке «Проверить состояние». В обзоре
  режим Live/установленная система определяется по факту, а не по тексту.
- **MVS Monitor**: заливка под графиком снова рисуется как площадь, а не
  как треугольник из левого верхнего угла.
- **mvsui.py**: `GLib.idle_add` вызывается через обёртку, которая всегда
  возвращает `False`; раньше источник с истинным результатом повторялся
  бесконечно. `background()` теперь умеет вернуть результат или исключение
  в главный поток.

### Виртуальная машина

- `tools/make-vm.sh --live` запускает ISO в окне QEMU без установки:
  изменения не сохраняются, закрытие окна возвращает в Linux. Скрипт
  работает с флешки рядом с ISO и сам находит образ, QEMU и KVM.
- Без аргументов скрипт запускает установленную VM, а если диска ещё нет —
  сам переходит в Live-режим. `--install` создаёт виртуальный диск.
- **Alt+Tab между системами**: окно по умолчанию не захватывает
  клавиатуру, поэтому `Alt+Tab` переключает на Linux, а клик по окну —
  назад в MVS OS. Для переключения окон внутри гостя есть `MVS_GRAB=1`.
- **Скорость в VM**: virtio-net вместо e1000, virtio-vga вместо std,
  iothread и writeback для диска, звук через PulseAudio/PipeWire.
  Видео можно ускорить ещё сильнее через `MVS_GL=1`.

### Сборка и CI

- `build.sh` больше не пытается сделать `chmod` для `90-mvs-live`, которого
  нет в исходниках: файл создаёт хук внутри chroot.
- В параметры загрузки добавлен `console=ttyS0,115200n8`: QEMU-тест снова
  видит журнал ядра и может поймать `Kernel panic`.
- GitHub Actions: pull request запускает только статику; полная сборка —
  на push в `main`, тег и вручную. В ручном запуске появились
  `publish_release` и `release_tag`. Добавлены очистка диска runner'а,
  `debian-archive-keyring` и 240 секунд на загрузку в QEMU.
- CI ставит live-build из Debian bookworm: в Ubuntu 24.04 лежит версия
  3.0~a57 2013 года, которая не понимает `--bootloaders` и
  `--iso-compression`. Debian-пакет зависит только от debootstrap.
- `build.sh`: сжатие squashfs задаётся настоящим параметром
  `--chroot-squashfs-compression-type xz`; опции `--iso-compression`
  в live-build не существует (xz и так используется по умолчанию).

## 1.0 «Aurora»

Первая полноценная версия: вместо «Debian с тёмной темой» — система
со своей оболочкой, приложениями, установщиком и правилами безопасности.

### Оболочка

- темы `MVS-Dark` / `MVS-Light` (GTK 3 + GTK 2) на базе Arc с палитрой MVS;
- набор иконок `MVS`, 16 фирменных SVG, наследует Papirus-Dark;
- три обоины: Aurora, Grid, Day;
- фирменный экран загрузки Plymouth (градиент MVS);
- панель: уведомления, быстрые настройки, часы с датой, звук, питание;
- горячие клавиши: `Super+S` — быстрые настройки, `Super+T` — терминал,
  `Super+E` — файлы, `Super+C` — Control Center, `Super+L` — блокировка;
- тема терминала, Thunar и GTK для новых пользователей;
- экран входа с фирменным фоном и темой MVS.

### Приложения

- `mvsui.py` — общий модуль: темы, запуск команд, привилегии, виджеты;
- MVS Control Center — 14 реальных разделов;
- MVS Store — три вкладки (наборы, поиск, журнал), установка и удаление,
  22 набора программ; наборы из сторонних репозиториев не притворяются
  доступными, а объясняют, что источник нужно подключить вручную;
- MVS Update — обновления с журналом и честными ошибками;
- MVS Monitor — графики и процессы;
- MVS Doctor — проверка диска, памяти, служб, ufw, AppArmor, обновлений
  и сети с текстовым отчётом;
- MVS Cleaner, MVS Backup;
- MVS Hub, MVS Welcome, MVS Quick, MVS Games, MVS About;
- обёртки `mvs-files`, `mvs-terminal`, `mvs-settings`, `mvs-theme`.

### Установщик

- Calamares: диск, пользователь, локаль, клавиатура, сводка, загрузчик;
- UEFI и Legacy BIOS, grub + shim;
- шаг `live-admin`: снимает Live-правила, включает ufw/AppArmor,
  удаляет live-пакеты, пересобирает initramfs без live-boot,
  убирает ярлыки установщика, проверяет sudoers;
- `mvs-install` запускается только из Live и только с подтверждением.

### Программы в образе

- LibreOffice Writer/Calc/Impress с русской локализацией и проверкой
  орфографии, Thunderbird, VLC, FFmpeg;
- GParted, GNOME Disks, SMART, NVMe, `lm-sensors`, `fwupd`, микрокод CPU,
  несвободные прошивки GPU;
- `light-locker` (блокировка экрана), `tumbler` (миниатюры),
  `xfce4-clipman-plugin`, `xfce4-sensors-plugin`;
- поиск файлов Catfish, связка ключей GNOME и `seahorse`;
- сеть: `smbclient` и сетевые папки в Thunar, `unrar-free`;
- печать и сканирование: `cups-browsed`, Avahi, `libnss-mdns`,
  `sane-airscan` — сетевые принтеры и сканеры находятся сами;
- терминал и диагностика: `htop`, `ncdu`, `rsync`, `git`, `curl`, `wget`,
  `mc`, `vim`, `jq`, `inxi`, `lshw`, `remmina`;
- `gdebi`, `synaptic`, `python3-pip`, `python3-venv`;
- AppArmor profiles и `apparmor-utils`;
- три дополнительные игры: судоку, шахматы (со Stockfish), четыре в ряд.

### Автоматизация

- `tools/build-local.sh` — ставит зависимости и собирает ISO на Debian 12;
- `tools/make-vm.sh` — создаёт диск VM, проверяет ISO и запускает QEMU
  без перезагрузки хоста; `--install` — первый запуск с установщиком;
- `tools/write-usb.sh` — проверяет SHA256, отказывается писать на системный
  диск, требует `YES` и пишет ISO на флешку;
- `tools/check-packages.sh` — сверяет все имена пакетов с архивом Debian
  bookworm до сборки;
- `PACKAGES-1.0.txt` — список пакетов и версий, вошедших в ISO;
- `docs/vm.md` — запуск и установка в виртуальной машине.

### Безопасность

- Live: sudo без пароля и polkit-правило — только для `mvs`, только в Live;
- установленная система: пароль, sudo, polkit, root не входит в графику;
- ufw: входящие `DROP`, исходящие `ACCEPT`, включён в установленной системе;
- AppArmor, sysctl-защита ядра, `sudoers.d/10-mvs-hardening`;
- apt принимает только подписанные репозитории;
- автоматические обновления безопасности без автоперезагрузки;
- zram-swap для машин с 2–4 ГБ RAM.

### Сборка и качество

- списки пакетов разделены на 5 слоёв: live, desktop, apps, installer, extra;
- хуки: брендинг, Live-политика, чистка;
- `build.sh`: проверки окружения, chmod, SHA256SUMS, BUILD-INFO, список
  пакетов, предупреждение о лимите 2 ГБ;
- `check.sh`: sh, XML/SVG, `.desktop`, иконки, пакеты, версии, Calamares,
  Python, JSON, YAML;
- GitHub Actions: имена пакетов → сборка → QEMU smoke (BIOS и UEFI) →
  релиз по тегу;
- документация: сборка, установщик, безопасность, архитектура, тесты.

### Исправлено по сравнению с 0.1

- версия системы больше не «0.1» в одном файле и «Live» в другом;
- `mvs-about` и `mvs-games` переписаны с zenity на общий GTK-модуль;
- удалены пустые/декоративные элементы интерфейса;
- Calamares не получает модули без конфигов;
- установленная система не остаётся с автологином и sudo без пароля;
- SSH-ключи и machine-id не попадают в ISO.

## 0.1

- Первый прототип: Debian 12 + XFCE, Live ISO, тёмная тема, панель,
  простые обои, пять терминальных игр.
